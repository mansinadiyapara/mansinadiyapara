# Performance Analysis

## 1. Objective

The objective of this experiment is to compare standard Python processing with NumPy vectorized processing when calculating total sales from datasets of increasing sizes.

The experiment measures:

- Execution time
- Input memory usage
- Correctness of results
- Performance as dataset size increases

The purpose is to select an appropriate approach based on actual measurements rather than assumptions.

## 2. Dataset Sizes

The experiment uses generated sales data with the following sizes:

- 10,000 records
- 100,000 records
- 1,000,000 records
- 5,000,000 records

Each record contains:

- Quantity
- Unit price
- Discount percentage

The same generated data is used for both processing approaches to ensure a fair comparison.

## 3. Methods Compared

### Method A: Standard Python

A Python loop processes each transaction individually.

For each record, the program calculates gross sales, applies the discount, and adds the result to the total.

**Advantages:**
- Easy to understand
- Simple to debug
- Suitable for many small tasks

**Limitations:**
- Python processes records individually.
- Large datasets may require more execution time.

### Method B: NumPy Vectorization

NumPy calculates net sales using array operations rather than an explicit Python loop.

The formula is:

Net Sales = Quantity × Unit Price × (1 − Discount Percentage / 100)

**Advantages:**
- Efficient numerical operations
- Often faster for large numerical datasets
- Convenient for array-based calculations

**Limitations:**
- May create temporary arrays that require additional memory.
- Requires familiarity with NumPy arrays and data types.

## 4. Measurement Process

The experiment uses `time.perf_counter()` to measure execution time.

Input memory is estimated using the `.nbytes` property of the NumPy arrays.

Both methods calculate the same total sales amount. The results are compared using `numpy.isclose()` to allow for small floating-point differences.

The experiment records:

| Metric | Description |
|---|---|
| Record count | Number of transactions processed |
| Python execution time | Time taken by the Python loop |
| NumPy execution time | Time taken by NumPy vectorization |
| Input memory usage | Storage occupied by the input arrays |
| Result comparison | Whether both calculated totals match |

## 7. Performance Interpretation

### Execution Time

Execution time indicates how long an operation takes to complete.

If NumPy takes less time than standard Python for the same dataset, NumPy performed better in that particular test.

The speedup can be calculated as:

Speedup = Python Execution Time / NumPy Execution Time

For example, if Python takes 2 seconds and NumPy takes 0.2 seconds, the measured speedup is 10 times.

This is an illustrative example, not an actual experiment result.

### Memory Usage

The `.nbytes` property reports the storage used by an individual NumPy array.

The total input memory is calculated by adding the storage sizes of the quantity, price, and discount arrays.

This does not measure the complete memory used by the Python process. Temporary arrays, Python objects, and other program overhead can increase actual memory consumption.

### Correctness

Performance is useful only when the calculation is correct.

The experiment compares the results from both methods. If they do not match within the chosen tolerance, investigate the calculation, data types, and floating-point precision before drawing conclusions.

## 8. Limitations

1. Execution time depends on hardware, software versions, and system load.
2. Measurements may vary between runs.
3. Input array memory is not the same as peak process memory.
4. Generated data may not represent every characteristic of real business transactions.
5. Matching totals does not prove that the business rules are correct.
6. The experiment compares two approaches for one numerical calculation; its results may not apply to every Python or Pandas operation.
7. Very large datasets may exceed available memory, so smaller test sizes may be necessary.

## 9. Conclusion

The experiment evaluates standard Python and NumPy vectorization using measured execution times, memory estimates, and result comparisons.

The final choice should be based on the actual measurements, available memory, correctness, readability, and requirements of the project.

The main lesson is that performance claims should be supported by evidence. Instead of assuming one approach is always faster, measure both approaches under the same conditions and document the results.
